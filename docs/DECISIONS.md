# 결정 기록

## 2026-09-27 — 학교 강당 테마와 실제 연결 이후

문제: 사용자가 학교 강당 분위기를 요청했고 실제 Studio 실행에서 미게시 장소의 저장 초기화 오류가 발견됐다. 선택지: 기존 라운지에 장식만 추가 / 무대와 창문을 갖춘 강당 구조로 변경. 결정: 전체 공간과 화면을 학교 강당으로 통일하고 대화 테이블은 공개된 중앙에 유지한다. 이유: 사용자의 명시적 디자인 요청을 반영하면서 소셜 플레이를 유지한다. 단점: 실내 천장과 관람석은 카메라·이동 검사 범위를 늘린다. 재검토: 실제 화면·모바일·통로 검증 후 조정한다.

임시 저장은 DataStore 핸들 자체를 만들지 않도록 수정했고 기존 라운지 1인 실행은 통과했다. 이후 자동 승인 검토에서 사용량 한도 오류가 발생하여 새 디자인의 Studio 반영·시각 검증은 보류했다. 기존 'Studio 연결 없음' 기록은 최초 작업 시점의 이력이며 현재는 실제 연결·도구 호출 성공이 확인되었다.

## 2026-09-27 — 첫 단계는 핵심 플레이 루프

문제: 전체 기획을 한 번에 구현하면 실제 재미와 저장 안정성을 검증하기 전에 복잡도가 커진다. 선택지: 모든 기능 동시 구현 / 12개 MVP 기능 우선. 결정: 질문·배정·코인·평판·저장을 먼저 구현하고 그룹·수집·과금은 후속 단계로 둔다. 이유: 사용자가 지정한 MVP 범위를 지킨다. 단점: 첫 버전의 코인 소비처가 없다. 재검토: 다중 접속 및 저장 시험 통과 후.

## 2026-09-27 — 첫 평판은 무료

문제: 코인 소비와 평판을 바로 연결하면 담합·간접 유료 평판의 검증 범위가 커진다. 선택지: 유료 평판 / 무료 평판 + 후속 시각 효과. 결정: 무료 5종, 동일 상대 24시간 제한, 수신자 하루 10회. 이유: 긍정 상호작용에 진입 비용을 만들지 않고 반복 농사를 제한한다. 단점: 반응을 많이 받는 정상 플레이어도 한도에 도달한다. 재검토: 실제 유저 분포 측정 후.

## 2026-09-27 — 저장 실패는 입장 중단

문제: 불러오기 실패를 새 계정으로 간주하면 기존 데이터를 덮어쓴다. 선택지: 임시 프로필로 계속 / 실패 시 중단. 결정: 운영에서 실패 시 입장을 중단하고 UpdateAsync로 단일 서버 세션 임대를 확보한다. Studio는 명시적 임시 모드. 단점: 장애 때 플레이할 수 없고 강제 종료 시 최신 저장 이후 진척은 유실될 수 있다. 재검토: 운영 지표·별도 거래 원장 도입 시.

## 2026-09-27 — 공개 기본 채팅

문제: 테이블별 커스텀 채팅은 개인정보 설정과 필터 우회를 초래할 수 있다. 선택지: 자체 채팅 / 공식 테이블 채널 / 공식 기본 채팅. 결정: 기본 TextChatService. 이유: 첫 버전에 맞는 단순한 공식 경로. 단점: 다른 테이블의 대화도 보인다. 재검토: 이용자 시험에서 대화 혼잡이 확인되면 공식 직접 채팅 권한을 적용한 채널 설계.

## 2026-09-27 — Studio 연결 없는 환경의 검증 경계

문제: 현재 Codex 대화에서 Studio 도구를 호출할 수 없다. 결정: 독립 실행 가능한 Luau 규칙·서버 모의 시험과 XML 장소 빌드를 수행하고 실제 엔진 검증은 미완료로 기록한다. 이유: 파일 생성이나 구문 통과를 플레이 성공으로 과장하지 않는다. 단점: 좌석 물리·모바일·실제 저장을 아직 증명할 수 없다. 재검토: Studio 연결이 확보될 때 QA 순서대로 진행.
