# 검증 절차

자동 시험과 실제 엔진 시험을 구분한다. 기본 Studio 임시 모드는 안전한 로컬 시험용이며 저장 성공 증거가 아니다.

| 단계 | 시나리오 | 합격 기준 |
|---|---|---|
| 1 | 1명 입장 | 대기 안내, 코인 자동 증가 없음 |
| 2 | 2명 입장 | 같은 테이블 배정, 각자 동일한 질문, 600초 표시 |
| 3 | 한쪽만 선택 | 다른 클라이언트에 선택 값이나 결과가 전달되지 않음 |
| 4 | 둘 다 같은/다른 선택 | 각각 MATCH +10 / DIFFERENT +0, 두 경우 모두 참여 +5 |
| 5 | 중복·예전 nonce·범위 밖 선택 | 코인·SYNC 추가 증가 없음 |
| 6 | 질문 시간 초과 | 미응답 쪽 선택을 추정하지 않고 다음 질문으로 진행 |
| 7 | 300초 활동 / 300초 방치 | 활동 누적 +50, 미활동 시간 보상 제외 |
| 8 | 완료 기준 미충족/충족 | +100 차등, Best Duo 조건 확인 |
| 9 | 긍정 반응 반복/자기 대상 조작 | 한 번만 증가, 자기 지급 불가 |
| 10 | 3·20·39·40명 | 각각 1·10·19·20쌍, 홀수 인원은 1명 대기, 좌석 중복 없음, 대기자 다음 라운드 우선 |
| 11 | 4명 연속 3라운드 | 직전 상대를 가능한 한 회피 |

| 13 | 재배정 제외 | 다음 라운드와 재접속 후 해당 상대 배정 없음 |

| 15 | 신고·차단·음소거 | 실제 Roblox 메뉴 접근, 안내가 성공 접수로 오해되지 않음 |

## 실제 저장 시험 (별도 테스트 경험)

`StoreName`을 테스트 전용으로 바꾸고 `StudioPersistence = true`로 설정한다. 저장 접근 허용 후 코인·평판·제외 기록을 얻고 정상 퇴장·재접속한다. 동일 사용자의 동시 서버 접근은 하나만 잠금을 획득해야 한다. 로드 실패는 빈 데이터 저장 없이 입장을 거부해야 한다. 저장 실패를 지속시키면 임대 만료 이후 보상이 중단되고 연결을 종료해야 한다.

서버 종료와 플레이어 퇴장이 겹칠 때 저장이 경합하지 않는지 확인한다. 강제 종료는 마지막 자동 저장 이후 손실을 일으킬 수 있다. 평판 제한도 마지막 저장 이후 되돌아갈 수 있으므로 출시 전에 지속 원장 방식으로 보완한다. 이미 반응을 받은 뒤 서버 이동·강제 종료를 반복하는 악용 시나리오를 포함한다.

시험마다 날짜, Studio 버전, 인원, 설정, 실제 결과, 오류 로그, 영상 또는 화면 증거를 TEST_RESULTS에 추가한다. 아직 실행하지 않은 항목에 체크 표시하지 않는다.

## 40명 확장 확인

게시 장소 최대 인원을 40명으로 설정하고 최신 파일로 시작한다. 40명에서 20쌍·40개 좌석, 39명에서 19쌍·대기 1명, 20번 테이블 답변 비공개와 보상, 다음 라운드 상대 변경을 확인한다. 41번째 사용자는 40명을 넘는 같은 서버에 입장하지 않아야 한다. 제외 관계를 만든 뒤에도 금지된 쌍이 생기지 않는지 검사한다. 실제 40명에서 프레임 속도·라운드 전환 지연·채팅 가독성·저장 오류와 종료 후 재접속을 기록한다.
