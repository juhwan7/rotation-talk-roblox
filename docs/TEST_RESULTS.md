모의 통합 시험은 운영 모듈 소스를 직접 불러와 최소 서비스 대체물로 실행한다. 테스트용으로 별도의 게임 규칙을 다시 구현하지 않는다. 실제 API 제한·요청 예산·물리 엔진·클라이언트 네트워크 지연은 모의 환경이 재현하지 못한다.

40명 그래프 500개 검사에 로컬 Luau 실행 기준 0.186초가 걸렸다. 이는 한 번의 개발 환경 측정이며 실제 Studio 지연·네트워크·물리 성능 보장이 아니다. 6명 그래프의 비트 마스크는 테스트 전수열거에만 사용하며 운영 매칭은 비트 마스크를 사용하지 않는다.

## 확인된 한계

1. 저장은 60초마다 수행한다. 강제 종료 시 마지막 저장 이후 코인·평판·제외 기록이 손실될 수 있다. 평판의 장애 시 정확히 한 번 처리 보장은 출시 전에 보완해야 한다.
2. 기존 라운지의 1인 화면 생성만 확인했다. 학교 강당 디자인의 실제 화면, 좌석 이동, 모바일 터치, 기본 채팅 메뉴는 미확인이다.
3. 같은 두 사람만 남으면 다시 같은 쌍이 된다. 제외 관계가 있으면 서로 매칭하지 않고 대기한다.
4. 중간 입장과 취소된 쌍의 대기는 다음 라운드까지 길어질 수 있다.
5. 빠른 질문 응답은 더 많은 참여 코인을 만든다. 최소 질문 간격과 시간당 발행량을 실측해야 한다.
6. 최대 인원 40명은 Roblox 장소 설정에서 별도 적용해야 하며 현재 미적용이다. 40명 동시 입장·저장 요청 집중·서버 종료 저장·공개 채팅 혼잡·모바일 성능은 실제 부하 검증이 필요하다.
7. 부계정·자동 클릭의 완전한 탐지, 계정 차단 목록 연계, 재배정 제외 해제 화면은 미구현이다.

다음 실제 시험은 [QA](QA.md)의 1~15단계와 별도 저장 시험 순서로 수행한다. 실제 시험 증거가 추가되기 전에는 출시 가능 또는 다중 접속 검증 완료로 표시하지 않는다.

## 실제 실행에서 발견한 오류와 수정

2026-09-27, 미게시 로컬 장소에서 `You must publish this place to the web to access DataStore` 오류가 발생했고 Main 모듈 로드와 클라이언트 Remotes 대기가 함께 실패했다. 임시 모드 판단 전에 GetDataStore를 호출한 것이 원인이었다. 호출을 임시 모드가 아닐 때로 제한한 뒤 다시 실행하여 빈 오류 로그, 라운지 생성, 12개 좌석, 1명 대기 화면, TemporaryData 표시를 확인했다. 이후 학교 강당 변경은 별도 빌드 검증만 수행했다.
